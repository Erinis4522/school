# AI 디펜스 — 캐릭터와 협력하는 5분 타워디펜스

초등~중학생용 오프라인 체험 게임. 8종 캐릭터 중 3명을 골라 배치하고 **행동 원칙**(가까운 적 / 위험한 적 / 특기 활용)을 정하면,
캐릭터가 스스로 표적을 골라 싸우면서 **실제 전황**을 말풍선으로 보고합니다. 방어선 위기와 기지 첫 피격 때(최대 2회)
캐릭터가 자기 원칙을 바꾸자고 **장점과 단점을 함께** 제안하고, 학생이 **바꿔보기 / 그대로 유지 / 다른 원칙 고르기** 중에서 결정합니다.

- 기준 문서: `AI_디펜스_PRD_v1.md` (2026-11-11)
- 엔진: **Godot 4.7.2 (standard) + GDScript**, 렌더러 **Compatibility (OpenGL 3.3)**, Windows 네이티브 2D
- 완전 오프라인: 네트워크 코드·외부 API·CDN 없음. 폰트(Noto Sans KR, OFL)까지 실행 파일에 포함
- 캐릭터: **v2 설계 — 성별·나이가 다양한 마을 사람 8명** ([`docs/CHARACTER_DESIGN.md`](docs/CHARACTER_DESIGN.md)). 그림 완료 3명(나래·서리·하은), 검객 임시 리그, 나머지 4명은 새 그림이 오기 전까지 도형으로 그린 SD 인물. 모두 대기·공격·특기 공격 모션. 교체 방법 → [`assets/README.md`](assets/README.md)

## 1. 실행

### 운영 PC (설치 없음)
1. 개발 PC에서 `build_exe.ps1` 실행 → `../build/AI디펜스/` 폴더가 만들어짐
2. 그 폴더를 통째로 운영 PC에 복사 (USB 등)
3. `시작.bat` 또는 `AIDefense.exe` 더블클릭

| 파일 | 용도 |
|---|---|
| `시작.bat` | 듀얼 모니터: 전투 화면 + 터치 화면 각각 전체 화면 |
| `한화면_테스트.bat` | 모니터 1대로 점검: 두 창을 한 화면에 나란히 (`--single`) |
| `창모드_시작.bat` | 듀얼 모니터지만 창 모드 (배치 확인용, `--windowed`) |
| `data/*.json` | 밸런스·문구 수치. 고치고 다시 실행하면 반영 (다시 빌드 불필요) |
| `assets/<분류>/*.png` | 그림 교체 폴더 (비어 있으면 도형으로 그림) |

실행 인자: `AIDefense.exe -- --single`, `--windowed`, `--arena-screen=0`, `--control-screen=1`

### 듀얼 모니터 연결
1. Windows **디스플레이 설정 → "디스플레이 확장"**
2. **터치가 엉뚱한 화면에 찍히면**: 제어판 → `Tablet PC 설정` → [설정] → 안내에 따라 터치스크린을 눌러 터치 화면 지정

   (`%APPDATA%\Godot\app_userdata\AI 디펜스\display.cfg`)
4. 모니터가 1대뿐이면 자동으로 분할 디버그 모드(두 창 나란히)로 뜸

## 2. 한 회차 흐름 (약 5분)

| 단계 | 터치 화면 | 전투 화면 |
|---|---|---|
| 대기 | 제목·안내문·[시작] | 제목, 안내, AI 설명 한 줄 |
| 선택 (목표 20초) | 카드 8장 → 누르면 위에서 상세 패널(이름·나이·소개·특징)이 내려오며 카드가 아래로 밀림 → [이 캐릭터로 확정] (3명 되면 [게임 화면으로]) | 확정할 때마다 그 캐릭터 초상화가 팀 자리로 떨어지며 등장 (3칸) |
| 배치·원칙 (목표 25초) | 캐릭터 누르기 → 지도 번호 누르기, 원칙 3버튼 (기본: 가까운 적 우선) | 놓인 캐릭터와 사거리 미리보기 |
| 전투 (≈165초) | 웨이브·HP·처치, 3명의 현재 원칙, 최근 보고 | 지도, 적, 공격 효과, 말풍선, 웨이브 배너 |
| 특별 제안 (최대 2회) | 현재→제안 원칙, 전황, **장점 카드 / 단점 카드**, 추정치, 버튼 3개(같은 모양), 30초 카운트다운 | 일시정지 + 해당 캐릭터의 큰 말풍선 |
| 결과 (30초 후 자동 초기화) | 기록·최종 작전·제안 결정 기록, [다음 학생 시작] | 생존 시간·웨이브·HP·처치·점수, 교육 메시지 |

- 웨이브 1(45초): 일반 위주 / 웨이브 2(50초): 빠른·갑옷 등장 / 웨이브 3(60초): 혼합 + 보스. 웨이브 사이 4초.
- 기지 HP 10, 일반 적 1·보스 2 피해. 점수 = 생존초×10 + 남은HP×50 + 처치×5 (+방어 성공 300). **제안 수락 보너스 없음.**
- 방치: 선택·배치 화면 75초 무입력 → 대기 화면. 제안 30초 무응답 → 기존 원칙 유지 후 재개. 결과 30초 → 대기 화면.
  (전투는 학생 입력 없이도 끝까지 진행되므로, 방치해도 최대 약 4분 안에 대기 화면으로 돌아옴)

## 3. AI가 하는 일 (기술적으로 정직한 설명)

이 게임의 AI는 **Utility AI(가중치 점수로 행동을 고르는 고전 게임 AI) + 전투 기록 분석 + 짧은 가상 전투 비교**입니다.
신경망·강화학습·생성형 LLM이 아니며, 플레이하면서 학습하지 않습니다. 대사는 사람이 미리 쓴 템플릿이고, **언제 어떤 숫자로 나올지만** 실제 게임 상태로 정해집니다.

### 3.1 표적 선정 (`src/ai/targeting.gd`, `specialty.gd`)
```
score(t, e) = wDistance × proximity + wDanger × baseDanger + wSpecial × specialtyFit
proximity  = clamp(1 − 거리/사거리, 0, 1)
baseDanger = clamp(0.75 × 경로 진행률 + 0.25 × (현재 속도/1.8), 0, 1)
```
| 원칙 | 거리 | 위험 | 특기 |
|---|---:|---:|---:|
| 가까운 적 우선 | 0.70 | 0.20 | 0.10 |
| 위험한 적 우선 | 0.10 | 0.70 | 0.20 |
| 특기 활용 | 0.10 | 0.10 | 0.80 |

사거리 밖 적은 후보에서 제외, 공격할 때마다 다시 평가, 동률이면 진행률 높은 적 → 작은 id.
`specialtyFit`은 캐릭터 고유 효과의 실제 기대치(검객: 함께 벨 이웃 수, 궁수: 이번 화살로 처치 가능성, 저격수: HP·방어, 화염: 밀집도×미화상, 빙결: 속도×미감속, 번개: 전이 가능 수, 폭탄: 폭발 반경 안 적 수, 표식: 미표식×위험도×다른 아군 사거리).

### 3.2 말풍선 (`combat_observer.gd`, `speech_scheduler.gd`)
- 관찰기가 0.25초마다 "지금 사실인" 후보만 계산 → 그중 우선순위(본진 위기 5 > 돌파 4 > 적 유형 경고 3 > 협력 2 > 긍정 1)가 가장 높은 것을 띄움
- 동시에 1개, 캐릭터별 15초, 전역 7초, 표시 2.2초. 전투는 멈추지 않음
- 같은 관찰이 누적 기록(빠른 적 돌파 수, 밀집, 단단한 적 생존 등)으로 남아 특별 제안의 근거로 인용됨

### 3.3 특별 제안 (`crisis_detection.gd`, `recommendation.gd`, `src/app/battle_session.gd`)
- **방어선 위기**: 진행률 ≥75% & 도착 예상 ≤8초인 적, 또는 진행률 ≥65% 적 3마리 이상 → 게임당 1회
- **기지 첫 피격**: 실제로 HP가 처음 줄었을 때 → 게임당 1회. 앞 제안 종료 후 전투 시간 18초가 안 지났으면 보관했다가 제안, 게임이 끝나면 취소
- **상태 복제 기반 가상 전투 비교** (구현함):
  1. 기준안(현재 원칙 유지) + 대안 최대 6개(캐릭터 1명 × 다른 원칙 2개)를 같은 시작 상태로 계산
  2. **앞으로 10초 미리 계산**: 지금 화면에 있는 적만 (아직 안 나온 적은 예지하지 않음)
  3. **최근 12초 다시 계산**: 약 12초 전에 저장해 둔 상태부터 지금까지를 각 원칙으로 다시 돌림. 그 사이 *실제로 나왔던* 적만 등장 → "그때 이 원칙이었다면?"
     (개발 중 측정해 보니 위기 순간에는 문제의 적이 이미 모든 사거리를 지나 있는 경우가 많아, 미리 계산만으로는 원칙 차이가 거의 0이었음. 그래서 다시 계산을 추가)
  4. 목적함수 `J = 기지 추가 피해×100 + 남은 위협`, 기지 피해가 줄거나 위협이 충분히(≥0.6, ≥8%) 줄 때만 변경 제안. 아니면 **"그대로 가볼까?"** 의견
  5. 장점 중 "기지 피해가 줄었어 (a → b)", "처치 수가 늘었어"는 **실제 계산 결과가 그럴 때만** 표시. 단점은 항상 1개 이상 (측정된 손해 + 원칙의 구조적 대가)
  6. 같은 (캐릭터, 원칙) 제안을 반복하지 않도록 비슷하게 좋은 다른 후보가 있으면 그것을 고름
- 전투 규칙에 난수가 없어 같은 상태 → 항상 같은 결과. 계산은 복사본에서만 하므로 실제 전투 상태는 바뀌지 않음 (테스트 9)
- 화면에는 "추정이에요 … 결과를 보장하진 않아요" 문구를 항상 같이 표시

### 3.4 명시해야 할 한계
- 게임 AI(Utility AI)이며, 경험으로 신경망 가중치를 학습하지 않음. "딥러닝으로 점점 똑똑해진다"는 설명은 틀림
- 제안은 지금 전황과 짧은 가상 전투에 근거한 **가능성**이며 정답·보장이 아님. 앞으로 나올 적은 모름

### PRD와 달라진 점 (사용자 지시 또는 근거 있는 조정)
- **스택**: PRD 권장(TypeScript+Vite+Canvas, 127.0.0.1 서버, BroadcastChannel) 대신 **Godot 4.7.2 네이티브** (사용자 지시).
  두 화면은 한 프로세스의 두 OS 창이라 서버·브라우저가 필요 없고, 게임 상태 계산은 `GameController` 하나만 함 → 중복 시뮬레이션이 구조적으로 불가능.
  PRD의 명령 ID/순서번호·ACK·상태 버전은 `GameController.command()`에 그대로 유지(테스트 11). "연결 끊김/재연결"은 해당 없음 — 조작 창은 닫기를 무시하고, 창 크기·화면이 바뀌어도 다시 꽉 차게 맞춤.
- **수치 조정** (밸런스 시뮬레이션 근거, 모두 `data/heroes.json`):
  검객 사거리 1.6→1.9 (설치 자리가 길에서 1칸 떨어져 있어 1.6이면 닿는 구간이 너무 짧음),
  빙결 피해 5→8·주기 1.3→1.1·사거리 3.2→3.3, 번개 피해 8→9, 화염 피해 10→9, 폭탄 피해 18→14·주기 2.3→2.5,
  표식 피해 3→5·주기 1.2→0.9·사거리 3.0→3.2·증폭 25%→35%. 그 밖의 수치는 PRD 예시값 그대로.
- **화상 피해**는 방어력을 무시 (지속 피해). 표식 증폭은 화상에도 적용.
